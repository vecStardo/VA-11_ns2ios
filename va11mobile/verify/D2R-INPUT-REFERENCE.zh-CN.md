# 参考 d2r-mobile 的输入方案（对照笔记）

用户提示：看 d2r 是怎么解决「点按进不了菜单」这类问题的。以下是源码对照与迁移结论。

## 1) 文档里 d2r 自己写明的做法

`d2r-mobile/dm/ios/Sources/front_ios.m`：
> 前端页面（主菜单 / 选角 / 建角 / 读取画面，即不在局内）：不显示摇杆与技能圆钮，触点直接当原生点击交给游戏界面
> （`dm_ui_touch` → 鼠标消息，dm_cursor.c）

`d2r-mobile/dm/host/dm_cursor.c`：
- `dm_ui_touch(phase, nx, ny)` **只登记**点击（phase 0/1/2/3）；
- `dm_ui_mouse_pump()` 在**「游戏取手柄那一拍」**（`hle_hid` 的 fill，主线程）每个**出图帧**消费一次，
  把点击变成**游戏自己的 UI 鼠标消息**（写游戏内存 / 调游戏函数），必要时再由宿主按确认键（`ui_auto_key(DM_BTN_A/B)`）或直接调 UI 函数（如切页签）。
- 菜单/面板层还靠 `dm_cursor_apply()` 把「光标目标」改写成左摇杆 / A 交给游戏。

要点：**不把点击留在前端线程直接生效**，而是队列化、按帧推进、与游戏的取手柄节拍同步——
这样游戏每次采样都一定看到干净的按下沿，不会因为采样错位丢掉点击。

## 2) 我们之前与它的差距

VA-11 之前是：触点在前端/脚本线程直接写进 `hle_touch` 的状态表，鼠标按钮再由 `GetMouseStates` 随时读——
按下只维持 65–120 ms，而且**按钮状态与游戏的采样帧没有对齐**，容易只被看到「按住中的一帧」而错过按下沿。

## 3) 已迁移的部分（本轮实现）

- `hle_touch.c` 新增**帧同步点击队列**：`dm_click_request(nx,ny)` 只登记；
  `dm_click_step()` 按**出图帧**推进「按下 → 按住 → 抬起」三拍（同一帧内多次取鼠标只算一拍）；
- `hle_hid.c` 的 `mouse_fill()` 每拍消费该队列 → 游戏读到带按下沿的鼠标状态；
- 点按（`tap_a_pulse`）同时登记一次帧同步点击 + 手柄 A 连拍 + Enter/Space 键盘注入。

## 4) 还没解决 / 下一步

VA-11 的 GM runner 菜单在拿到上述全部输入后仍不响应。下一步对齐 d2r 的另一半做法：
1. 在按住的那几拍打日志，确认游戏**确实在这一拍读到 button=1**（现在 1 秒节流日志看不到 2 帧的按下窗）；
2. 仿照 `dm_cursor_apply`：找到 VA-11 菜单的**选中项 / 光标变量**（guest 内存），由宿主直接改写选中项再交给游戏一次「A」，
   而不是依赖游戏自己处理点击；
3. 若菜单其实由 `device_mouse_*` 驱动，则要确认 GM runner 的 device 索引与 `GetMouseStates` 的对应（当前 device 0）。
