## 已知事实

1. **数据层：汉化文本确实在 `game.win` 里**
   - 在游戏数据里找到成片中文串（例：`可爱的粘土房屋`、`卖萌游戏海报`、`全息植物`，共 ~1000 段 CJK 连续串），
     同时也有日文串（~790 段假名串，例：`ここは、存在すべきでない街。`）。
   - 说明这一份 `game.win` 是**中日文都在**的文本集合，不是「整体替换」。
2. **游戏自带三种语言按钮**
   - 游戏数据里出现 `eng_button_inst` / `jp_button_inst` / `cn_button_inst` 三个实例名，
     以及语言名 `English` / `日本語` / `简体中文`，和 `os_get_language` / `ja` / `zh` 三个标识。
   - 推断：游戏在设置页提供 英/日/简中 三选一，并可能用系统语言自动选。
3. **当前 iOS 上默认显示日文**（开场旁白、标题菜单、SAVE/LOAD 均为日文）。

## 当前结论

- 汉化文本在数据里、可被解析；**没生效的是「选择哪种语言」这一步**。
- `Settings.json` 的 `Language` 整数项（试过 1、2）和宿主 `nn::oe::GetDesiredLanguage`（试过 en-US / zh-Hans）
  **都没有改变文本语言** —— 说明文本语言不是由这两条路决定的，或下标不是我们猜的值。
- 尚未验证的路径：进游戏设置页用「简体中文」按钮切换，然后**对比切换前后的存档/设置文件**，
  找出真正承载文本语言的键（很可能在 `Settings/` 下另一个文件，或 `Settings.json` 里另一个键名）。

## 追加（2026-10-17 23:35）：两条重要修正 + 一条确证

### 确证：游戏确实来查系统语言

在 `hle_oe.c` 的 `nn::oe::GetDesiredLanguage` 里加了一次性日志后实测启动：

```
[dm] [lang] nn::oe::GetDesiredLanguage → zh-Hans（游戏第一次查语言）
```

即：游戏**确实调用了**系统语言查询，宿主也返回了 `zh-Hans`，但最终文本仍是日文。
→ 问题落在「runner/游戏把 LanguageCode 映射成语言编号」这一步（或 `lango_map` 里没有 zh 项），
而不是宿主没给语言。

### 修正一：`Settings/Settings.json` 是 d2r 宿主遗留，不是 VA-11 的语言存储

`Settings.json` 里的键（`AutoMapMode`、`Item Name Display` 等）属于 d2r-mobile 的自定义设置，
是宿主 `hle_fs.c` 的触屏缺省逻辑写下的；VA-11 自己不读它。因此之前「改 `Language` 下标无效」是预期行为，
不再作为语言结论。

### 修正二：VA-11 的文本语言真正相关的是

- 游戏数据里有 `lang_val` / `lango_map` / `pure_lang` / `lang_select` / `Language#Change` 等标识；
- 剧情文本是**数据内文件**：`scripts/eng/*.txt`、`scripts/jp/*.txt`、`scripts/chn/*.txt`（同一份 game.win 内），
  即语言切换会换整组脚本目录；
- 游戏自己的配置里出现 `\\Waifu Preferences` + `configuration`/`language` 写入串（`file_text_write_string`），
  容器里对应的文件是 `Documents/save/Waifu Preferences.txt`（8 个数字，疑似含语言项）。

## 结论（2026-10-18 00:10，已在模拟器验证）

**根因找到了：这份汉化补丁把中文放进游戏的「英文」语言槽。**

- 宿主返回 `zh-Hans` → 游戏落到日文（中文槽不存在，回退日文）；
- 宿主返回 `en-US` → 提示与对白**整片变中文**：
  - 标题提示变成「按 A 键开始游戏」（`iosapp/out/cn_p1_rot.png`）；
  - 开场对白变成中文（`iosapp/out/evidence_zh_dialogue.png`：「这是拉斯维加斯繁华古老的幽儿峡吧。可根本就不想向超级奢侈的破地方迈近……」）。

### 修复
`iosapp/Sources/main.m` 的 `boot_env()` 里设置默认 `DM_LANG=en-US`（用户显式设置了就不覆盖）：
汉化数据在英文槽，所以 VA-11 iOS 缺省按 en-US 走，开箱即中文。

### 之前假设的最终判定
| 假设 | 结论 |
|---|---|
| 系统语言查询没被调用 | ❌ 有调用（`nn::oe::GetDesiredLanguage`，日志确证） |

| 语言映射缺 zh、需按英文槽 | ✅ 正确：`en-US` → 中文 |
